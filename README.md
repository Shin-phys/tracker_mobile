# MotionTrace Mobile

トレースアプリ Ver.2 のスマートフォン専用版です。
追跡・スケール校正・平滑化のアルゴリズムは Ver.2 と同一（`src/utils/` をそのまま流用）なので、
同じ動画からは同じ数値が出ます。変えたのは **画面構成と入力方法だけ** です。

## 起動

```bash
npm install
npm run dev
```

`vite.config.ts` で `server.host: true` にしてあるので、起動時に表示される
`http://192.168.x.x:3000/` を同じ Wi-Fi のスマホで開けば実機で試せます。

ビルドは `npm run build`（出力は `dist/`）。

## 画面構成

```
┌──────────────┐
│ TopBar       │ OpenCV の準備状況・記録点数
├──────────────┤
│ 映像ステージ  │ ピンチズーム／パン、ツール操作
├──────────────┤
│ 再生バー      │ 再生・コマ送り・やり直し・始点へ・再生速度・シーク
├──────────────┤
│ シート        │ トリム／対象／校正／設定／データ（高さ 3 段階）
├──────────────┤
│ タブバー      │
└──────────────┘
```

シートの上端の横棒はドラッグで高さを変えられます。タップで「半分 ⇄ 広い」、
同じタブをもう一度押すと閉じて映像が広くなります。

## 指の使い分け

映像の上では **指の本数で役割が変わります**。

| 操作 | 動き |
| --- | --- |
| 2本指ピンチ／ドラッグ | いつでも拡大縮小・移動 |
| 1本指 | 画面左のツールバーで選んだツールの操作 |

タブの並びは、そのまま**作業の順番**になっています。
トリム → 対象 → 校正 → 設定 → データ。

ツールは 6 種類です。

- **移動**（手のアイコン）— 1本指でも映像を動かす。誤操作を避けたいときの既定状態。
- **枠**（四角）— 追跡枠の指定。**2 段階**に分かれています。
  1. **中心を決める** — 映像を押すと拡大鏡が出ます。指を動かして対象の中心に合わせ、離すと確定
  2. **大きさを決める** — スライダーで枠の大きさを合わせて「決定」。中心を取り直すこともできます

  1 回のドラッグで中心と大きさを同時に決めさせると、指ではどちらも精度が出ません。
  枠の中は、マーカーと一緒に動くものだけで埋めてください（動かない背景が入ると精度が落ちます）。

  枠ツールに入ると、**記録が始まるコマへ自動で戻ります**。枠はそのコマの画から
  テンプレートを作るので、別のコマで置くと追跡が始まりません。
- **修正**（十字矢印）— 一時停止中に、ずれた追跡点をドラッグして正しい位置へ直します。
  直せたかどうかは画面上部の帯に出ます。

画面上の追跡点・手動記録の点・修正の点は、**中心に隙間のある十字**で描いています。
塗りつぶした丸だと、狙っている画素そのものが自分の描画で隠れてしまうためです。
自動追跡の精度には影響しませんが、指で打つ・直すときの精度は変わります。
手動記録の誤差は 1/Δt² で速度・加速度へ拡大するので、狙いのばらつきが半分になれば
同じコマ送り幅で速度の誤差もそのまま半分になります。
- **手動記録**（カーソル）— コマごとに対象をタップして手でデータを作ります（下記）。
- **原点**（照準の的）— 座標の原点にしたい位置をタップします。
- **校正**（照準）— 校正タブで「指定を開始」を押すと現れます。

## 速い対象: 初速を教える

トラッカーは**等速度予測**を持っていますが、最初の 1 コマだけは速度がまだ無く、
予測なしで「前のコマと同じ場所」を中心に探します。1 コマの移動量が探索窓
（枠の大きさ × 探索範囲）を超える対象は、**ここで必ず破綻します**。
投げた直後の球、衝突直後の台車などがこれに当たります。

対象タブの **「速い対象: 数コマ先でもう一度指す」** を押すと、枠を置いたコマから
数コマ送った状態になります。そこで**枠から、対象が移動した先まで指でなぞる**と、
矢印が引かれます。この矢印が「数コマでどれだけ動いたか」で、ここから
1 コマあたりの移動量が決まり、追跡の最初のコマから予測が効くようになります。
指を離すと、記録が始まるコマへ自動で戻ります。

効き目はもう一つあります。予測が当たっている限り、探索窓が吸収すべきなのは
「移動量」ではなく**「移動量の変化」**だけで済みます。実測した自由落下では
44px/コマ に対して 1.1px/コマ、40 倍の差でした。探索窓を小さく保てるぶん、
背景の似た模様に吸われる確率が下がります。

静止から始まる運動（自由落下など）では要りません。1 コマの移動量が対象より
大きいときだけ、「このままでは追えません」と出ます。それ以外は黙ります。

**指した点は検算にも使われます。** 再生してその時刻に来たとき、追跡位置が
指した位置から離れていたら「別のものを掴んでいます」と警告します。
マッチングスコアは高いまま別の物を追えてしまうので、**走らせた直後に
間違いへ気づける手がかりはこれだけ**です。

やり直しをすると、戻る先のコマでの速度が軌跡から拾い直されます。

## 手動記録

自動追跡が使えない対象（変形する物体、低コントラスト、遮蔽が多い）はコマごとに手で指します。

1. コマごとに対象をタップする
2. そのコマの全対象を打つと、自動で設定コマ数だけ進む
3. 動画を 1 周すれば終わり

打つ順番は案内されますが、**物体チップを押せば指名**できます。取り消しは 1 点ずつ遡れます。
記録は自動追跡と同じデータに入るので、自動で追えた区間と混ぜて使えます。

**コマ送り幅が精度を決めます。** 加速度は 2 回微分なのでタップのぶれが 1/Δt² で拡大されます。
細かく打つほど良い、ではありません。合成データでは 1 コマおき（実時間 4.2ms）でばらつき 40.7%、
8 コマおき（33.3ms）で 0.7% でした。スライダーには実時間の間隔が ms で併記され、
撮影 fps から推奨値が自動で入ります。

ドラッグ中は指で隠れる部分を **虫めがね**（3倍）で表示します。数 px の精度が要るときはこれを見てください。

## マーカーの選び方

7 種類の形状を、追跡アルゴリズムそのもので 12,400 回試行して比べた結果です
（PC 版リポジトリの `scripts/marker-benchmark/`。印刷用 PDF もそこにあります）。

| 状況 | 推奨 | 位置誤差 |
|---|---|---|
| 回転しない対象（台車・落とす箱） | **太い十字**（腕幅 = 径の 1/4） | 0.069 px |
| 回転する対象（球・輪・振り子のおもり） | **同心円**（白 D / 黒 0.62D / 白 0.31D） | 0.078 px |
| 迷ったとき | **白地に黒丸**（黒の径 = 0.6D） | 0.116 px |
| （現行）白い丸シール | 非推奨 | 0.251 px |

大きさは画面上で **20〜30px**。実寸 = 視野の横幅 [mm] ÷ 横の画素数 [px] × 25。
線幅は画面上で 3px を切らないこと。

- **回転する対象に十字・市松・4分割を使わないでください。** 15 度回っただけで一致度が
  0.98 → 0.51 まで落ちます（LOST 判定は 0.45）。同心円と丸は 0.97 以上を保ちます。
- **方眼紙や目盛りのある背景では、白い丸シールが破綻します。** 実測で 150 回中 100 回、
  1px 以上外しました。印刷したマーカーは 7 種すべて破綻ゼロです。

**枠の中身**（誤差 13〜34 倍）のほうが形状の差（最大 4 倍）より一桁効きます。
まず枠の取り方を直してから、形状を検討してください。

## スケール校正

PC 版と同じ 3 モード（平面（四隅）／2点間／追跡枠の幅）です。スマホでは操作だけ変えています。

- **平面（四隅）**: 左上 → 右上 → 右下 → 左下 の順に**タップ**。
- **2点間**: 端から端まで**なぞる**か、**2回タップ**。
- 置いたあとは点を直接ドラッグ、または校正タブの**十字キーで 1px ずつ**動かせます
  （キーボードが無いスマホでは、これが矢印キーの代わりです）。
- 校正が完了したあとは、タップしても点が置き直されません。
  やり直したいときは「四隅を取り直す」「線を引き直す」を押してください。


### 基準は長く取ってください

縮尺は「実寸 ÷ 基準のピクセル長」なので、**校正の誤差は基準の長さに反比例します。**

| 基準の長さ | 端を 1px ずらしたときの誤差 |
|---|---|
| 33 px（2cm の球） | 3.0 % |
| 100 px | 1.0 % |
| 500 px（30cm の物差し） | 0.2 % |

この誤差は長さだけでなく、**速度にも加速度にもそのままの倍率で乗ります**。
直径 2cm の球を基準にして両端を 4px ずつ外に取ると 24% ずれ、重力加速度が
9.8 ではなく 7.9 になります。実際に起きた話です。

基準が 150px を切ると警告を出します。定規や、両端に十字を印刷したスケールバーなど、
**長くて端が一意に決まるもの**を基準にしてください。

校正点は**中を塗らない十字**で描いています。塗りつぶした丸だと、狙っている目盛りが
自分の描画で隠れ、終点が目分量になります。それがそのまま上の誤差になります。

**原点**は「原点」ツールでタップして指定します。CSV の `X, Y` がその点からの値になります。
未指定なら画像の左下（`Y軸を上向き` が OFF なら左上）が原点です。

## 解析区間（時間範囲・トリムタブ）

任意ですが、**最初にここから始めるのが確実**です。指定しなければ動画全体を使います。

進め方は、終わりのコマで「終点」→ **始点へ**（⏮）で戻る → 始まりのコマで「始点」→
そのコマのまま対象タブで枠を置く。この順にすると、枠を置いたコマと区間の始点が
必ず一致します。ずれると「始点のコマに物体がいない＝追跡が始まらない」になるので、
手順で潰しておくのが確実です。

始点・終点のボタンは、**トリムタブを開いている間だけ**映像の下に出ます。
どのタブでも出していると、使わない時間のほうが長いのに場所だけ占めるためです。

実験動画の頭と尻には、必ず使えない時間が入ります。装置の準備、手がフレームに入っている区間、
着地後の跳ね返り、転がって止まるまで。これを含んだまま解析すると 2 つが壊れます。

- **Butterworth の自動遮断周波数** — 記録全体に対して遮断周波数を 1 つ選ぶので、静止区間や
  衝突の不連続が混ざると、肝心の運動区間に対して不適切な値が選ばれます。
- **中心差分** — 衝突の瞬間をまたいだ 1 点だけ、物理的に意味のない速度が出ます。

### 使い方

再生バーの下の **始点 / 終点 / 解除** で指定します。

1. 運動が始まるコマまでコマ送りし、**「始点」**
2. 運動が終わるコマまで進めて、**「終点」**

片側だけの指定もできます。シークバーには区間が帯で表示されます。

### 何に効くか

区間は **記録と解析の両方**に効きます。

| | 動き |
|---|---|
| 記録 | 区間外は追跡も記録もしない。**終点で自動停止**する |
| 再生 | 区間の外から再生を始めると、まず始点へ送ってから再生する |
| やり直し | 動画の先頭ではなく**区間の始点**へ戻る（軌跡は消え、枠は初期位置へ戻る） |
| 解析 | グラフ・フィルタ・CSV が区間内のデータだけを使う |

終点の自動停止があるので、片手で端末を持ったまま「終わりを見張って停止ボタンを押す」
必要がなくなります。押し遅れて余分なフレームが混ざる事故もこれで消えます。

**あとから狭めるのは非破壊です。** 記録済みのデータは残るので、区間を狭めればグラフ・CSV が
その区間だけを使い、広げれば元に戻ります。取り直しは不要です。

区間内が **20 点を切ると警告**が出ます。Butterworth はデータから遮断周波数を決めるので、
点数が減ると選択そのものが不安定になります。

区間は「この動画の何秒から何秒まで」なので、動画を読み込み直すと解除されます。

## やり直し（取り直し）

再生バーの **やり直し**（↺）は 3 つを同時に行います。

1. 記録した軌跡を消す
2. **追跡枠を、戻る先のコマで物体がいた位置へ戻す**
3. 記録が始まる時刻へ送る（区間の始点 → 無ければ枠を置いたコマ → 無ければ先頭）

2 が要る理由は、枠が追跡中に毎フレーム上書きされるからです。追跡が終わった時点で
枠に入っているのは「物体が最後に到達した位置」なので、それを残したまま巻き戻すと、
物体のいない場所でテンプレートが作り直され、その場で破綻します。

**戻す先は 2 段階です。**

- 直前の走行の軌跡が残っていれば、**戻る先のコマ（＝ 3 の時刻）でその物体がいた位置**へ
  枠を移します（大きさは変えません）。
- 軌跡がまだ無ければ、最初に置いた位置へ戻します。

最初に置いた位置へ戻すだけだと、区間の始点をあとから動かした場合や、物体ごとに別のコマで
枠を置いた場合に、**枠と映像が別のコマを指したまま**になります。これが
「やり直すたびに枠を置き直す」原因でした。

結果として **同じ区間・同じ初期枠なら、何度取り直しても同じ数値が出ます。**

手動で打った点があるときは、消える点数を示して確認します。

### 枠を置いたコマと区間の始点

テンプレートは **枠を置いた瞬間のコマの画**から作られます。区間の始点がそのコマとずれていると、
始点のコマに物体がいない＝追跡が始まらない、ということが起きます。
ずれているときは警告と **「枠のコマを始点に」** ボタンが出ます。

複数の物体の枠を別々のコマで置いた場合も警告します。戻れるコマは 1 つしかないので、
どちらかは必ず外れます。


## コマの点検

記録が終わると、**位置の 2 階差分**が一定かどうかを自動で調べます。等加速度なら
これは一定になるはずなので、飛んでいるコマは次のどちらかです。

1. **動画側のコマの時刻ずれ** — スロー撮影を焼き直した動画には、ときどき半コマ分
   ずれた絵が混ざります。実測した例では、240fps 刻みの素材を実効 120fps へ間引く
   過程で、素材のコマが欠けている場所だけ隣の絵が使われていました。
   **追跡がどれだけ正確でも、これは動画に焼き込まれているので消せません。**
2. **追跡の失敗** — ブレて別のものに一致した、画面端で止まった、など。

該当するコマは映像上で**橙の破線**で囲みます。点は消しません。消すと「無かったこと」に
なり、なぜ速度が暴れているのか説明できなくなるからです。

速度に直してから探さないのは、微分がノイズを増幅するうえ、中心差分のせいで
1 コマの異常が前後 2 点へ逆向きに散り、原因のコマが特定できなくなるためです。

### ブレの限界

**1 コマの移動量が枠の 0.7 倍を超えた時刻**も併せて出し、区間の終点として提案します。
対象が自分の大きさ以上に流れて写ると、テンプレート照合の中心はもう対象の中心では
ありません。ここから先のデータは、追跡できているように見えても使えません。

対策は「明るくする」「撮影 fps を上げる」「対象を大きく写す」のどれかです。

## 追跡が暴れたら止まります
追跡が飛んだコマを見つけたら、**その場で再生を止めます**。

判断に使っているのは 2 つです。

- **相関のピークが探索窓の縁に出た** — 本当の最適解が窓の外にあるかもしれない、
  つまり追い切れていない状態。サブピクセル補間も効かないので、座標が整数に
  なって現れます。実際の衝突動画では、暴れたコマの多くがこれでした
- **1 コマの移動量が、直前までの中央値から大きく外れた**（3 倍以上）

マッチングのスコアは高いまま壊れるので、ロスト判定では拾えません。

### 衝突と見分ける

**飛んだのが 1 つだけなら追跡の失敗、2 つ以上が同じコマで飛んだら衝突**として
扱い、止めません。運動量のやりとりは同時に起きるので、本物の衝突では
両方の速度が同じコマで変わります。片方だけが飛ぶのは物理的に起こりません。

実際の衝突動画（2 物体）で確かめたところ、暴れた 4 コマをすべて拾い、
衝突そのものは 1 件も誤検出しませんでした。

### 止まったあと — 直すのではなく捨てる

飛んだコマには **✕** を付け、**軌跡の線をそこで切ります**。点そのものは消しません。
消すと「無かったこと」になり、誤検出だったときに戻せません。

そのうえで案内に 3 つ出ます。

- **ここから取り直す** — 戻す位置を選ぶ画面に入ります（下記）
- **この点を手で直す** — そのコマへ送って修正モードに入ります
- **誤検出・続ける** — ✕ を外し、同じあたりでは当分検出を見送ります
  （見送らないと、再開した次のコマで同じ理由でまた止まります）

### 戻す位置の選び方

直前の記録点が候補として映像の上に並びます。**判断の基準はひとつだけです。**

> **点がマーカーに乗っている最後のコマ**

1. **アプリが答えを置いています** — 移動量が普段から外れ始めた 1 つ手前が
   最初から選ばれています（白い二重の輪）。そのままで良ければ 3 へ
2. 違うと思ったら **◀ ▶**（または軌跡を指でなぞる）で動かします。
   選択を動かすと**そのコマへ動画が送られ**、虫めがねが選択中の点を
   拡大するので、点がマーカーの上に乗っているかを見て決められます。
   赤い点は移動量が普段から外れたコマです
3. **「ここで切る」**。それより後の記録を捨て、枠をその位置へ戻します
4. 枠を置き直して再生を続けます

候補を選ぶとそのコマへ送るのは、**この判断が映像を見ないと決められない**
からです。止まったコマのまま点だけを並べても、どれが正解なのかは分かりません。

### 捨てたコマを手で埋める（橋渡し）

切ったあと、**同じコマをもう一度自動で追わせても同じ結果になります**。
壊れた理由は「そのコマの画と、そのコマの動きの大きさ」で決まっていて、
枠を引き直してもどちらも変わらないからです。枠の位置そのものは記録から
分かっているので、置き直しても新しい情報はありません。

**本当に足りないのは「跳ねたコマで対象はどこに居たのか」です。**

そこで切ったあとは、**捨てたコマを人が指して埋めます**。捨てた最初のコマが
出るので、対象の中心をタップしてください。そのコマの対象が揃うと
1 コマ進みます。2〜3 コマ指したら **「自動に戻す」**。

難しいコマを自動に任せないことで、3 つが同時に片付きます。

1. **捨てたコマが本来の位置で埋まる** — データに穴が開きません。
   2 階差分も当てはめも、穴があると前後 2 点に影響が散ります
2. **最後の 2 点から 1 コマあたりの移動量が出る** — 再開の初速になります。
   トラッカーは直前のコマからの変位を予測に使うので、作り直した直後の
   1 コマだけは予測がありません。止まった場所はまさに予測が外れた場所です
3. **テンプレートを「難しい場面の先」で作り直せる** — 衝突やブレの瞬間を
   自動で越えさせる必要がなくなります。ここが一番効きます

複数の対象があるときは、各コマで全部を指してもらいます。1 つだけ埋めて
コマを進めると、もう一方にだけ穴が開いた記録になり、2 物体間の距離も
「同じコマの組」も崩れるからです。

そして自動に戻す瞬間に、**その枠が本当にその対象を見つけられるかを実測します**。
最初に指したコマのテンプレートを、最後に指した位置で探してみます
（どちらの位置も人が教えてくれているので測れます）。

測り方は、ピークの**鋭さ**です。

```
鋭さ ＝ (指した位置の相関) − (テンプレートの 35% だけずらした 8 方向の平均)
```

枠の中に「コマが変わっても形の変わらないもの」が入っていなければ、ずらしても
相関が落ちません。**どこへずれても同じくらい一致する**ので、スコアは高いまま
位置だけが流れます。ロスト判定には引っかかりません。

合成データでの実測（別ノイズを乗せた 2 コマ間で測定）

| 枠の置き方 | 鋭さ |
|---|---|
| 一様な物体の内側だけを枠 50 で囲む | **−0.03** |
| 同じ物体を輪郭まで含めて枠 180 | 0.89 |
| 一様な壁の上の白シールを枠 30 | 0.99 |
| 物体の縁をまたぐ枠 50 | 0.50 |
| テクスチャ背景だけを枠 40 | 1.00 |
| 何もない一様な壁を枠 30 | **0.01** |

合格側はすべて 0.5 以上、滑る側は 0 近傍なので、**0.2** で分かれます。

**1 コマだけでは測れません。** 同じコマで測ると、センサーノイズが「模様」として
効いてしまい、一様な面でも鋭さ 1.0 が出ます（実測）。ノイズは次のコマに同じ形で
現れないので、追跡の役には立ちません。だから測定には必ず別のコマを使います。

滑ると分かったときは、**枠を広げながら測り直して、最初に合格する大きさを探します**。
直径 176px の一様な物体では 50〜120px がすべて 0 近傍で、150px で 0.89 に跳ねました。
輪郭が入ったところで初めて「形の変わらないもの」が枠に入ります。

見つかれば **「枠を ◯px にして置き直す」** が出ます。押すと中心はそのまま、
大きさだけ測った値になった状態で置き直せます。同じコマで置き直すだけなら、
手で指した初速はそのまま生きます。

広げても見つからないときは、**枠の大きさでは解決しません**。その場所に追える
模様が無いということなので、マーカーを貼るか、模様のある部分が入るように
囲み直してください。

既定が「取り直す」なのは、**1 点を直しても足りない**からです。テンプレートが
別のものに乗り移るまでには、たいてい数コマのじわじわしたドリフトが先行します。
移動量が中央値から 3 倍外れた時点でやっと検出できるので、そこまでの数コマは
すでに汚れています。直した 1 点の手前に汚れた点が残り、壊れたテンプレートも
そのままなので、再開すれば同じ場所でまた壊れます。

切り落とすと**トラッカーも全部捨てます**。枠は「残した最後のコマで物体がいた
位置」へ移るので、そのまま置き直して再生を続けられます。

### 1 点だけ消す

グラフを見て後から外れ値に気づくこともあります。修正モード中に
**「この点を消す」**でその時刻のその対象の点を消せます。

対象が別のものに完全に乗り移った点や、物体が隠れて写っていないコマは、
正しい位置が存在しないのでドラッグでは直せません。消すのが唯一正しい処理です。
当てはめも 2 階差分も、1 点の跳ねで台無しになります。

止まったときは修正ツールに切り替わります。正しい位置へ点をドラッグするか、
枠を取り直してください。

## 探索範囲は「移動量」ではなく「移動量の変化」で決まる

**探索窓は狭いほうが良いです。** 広い窓は、似た模様に乗り移る機会を増やすだけで、
追跡の役には立ちません。

等速度予測が当たっている限り、窓が吸収すべきなのは**移動量ではなく移動量の変化**です。
実測した自由落下では、1 コマ 44px 進む場面でも**予測の外れは 1.1px**でした。40 倍の差です。

それなのに以前は窓を「枠の大きさ × 探索範囲」で決めていました。枠 40px・
探索範囲 1.2（旧既定）なら半径 48px。必要の 40 倍の範囲を探していたことになります。
**枠を大きくすると窓も比例して大きくなる**ので、「枠を広げる」という対処が
同時に「似た模様に乗り移りやすくする」副作用を持っていました。

合成データでの実測（直径 18px の白シール、経路の外に同じ印が並ぶ）

| 探索半径 | 40 コマ後の最大誤差 |
|---|---|
| 48px（枠 × 1.2・旧既定） | **680px（別の印に乗り移り）** |
| 24px | 0.0px |
| 10px | 0.0px |
| 5px | 0.0px |

一方、速度が急に変わる場面では窓が要ります。衝突で 1 コマの移動が
+18px → −12px に反転する場合、30px の窓が無いと見失います。

そこで現在は

```
普段の半径 ＝ max(4px, 予測の外れ量 × 4 ＋ 3px)   ただし 枠 × 探索範囲 を上限
探索範囲の既定は 1.0（枠の大きさと同じ半径が上限）
縁に当たったら、1 回だけ上限まで広げて引き直す
```

としています。これで両方成立します（上の表の全ケースで 0.0px、衝突でも 0.0px）。
平均の探索半径は 48px → **4〜8px** に下がり、処理も軽くなります。

速度がまだ無い最初の 1 コマだけは、どれだけ動くか分からないので上限で探します。
**2 点目を指しておくとこのコマも狭い窓で済む**ので、速い対象では二重に効きます。

### 飛んだ・見失ったときに出る「次に試すこと」

追跡が飛んで止まったとき、および**解析区間の中で見失ったとき**に、
そのまま押せるボタンが出ます。

- **探索範囲 1.0 → 0.8** — 目印（丸シールなど）を使っているなら、目印そのものは
  見分けがつくので窓は狭いほど有利です
- **再生速度 1/4 → 1/8** — コマを取りこぼすと、記録の上では 1 コマの移動量が
  倍（2 コマ落とせば 3 倍）になり、探索窓を超えます

どちらも下限に達していれば出ません。区間の外で見失った場合も出しません
（もう写っていないだけなので）。

### 画面で確認できます

選択中の対象には、**実際に探している範囲**が薄い点線で出ます。
探索範囲の設定は数字だけでは決められないので、枠と一緒に見て判断してください。
等速で追えている間はごく小さいのが正しい姿です。

### 枠は「大きいほうが良い」わけではありません

枠に求められるのは大きさではなく、**コマが変わっても形の変わらないものが
入っていること**だけです。白い丸シールが背景から分かれて写っているなら、
シールとその周りが入る小さな枠で十分で、広げる意味はありません。

「枠を広げてください」と出るのは、**枠が一様な面の内側に収まっている場合だけ**です
（ピークの鋭さが 0.2 を下回ったとき）。大きな白い物体の内側だけを囲んだときが
これに当たります。そのときだけ、輪郭が入るまで広げる必要があります。

## 時間軸（スロー動画）

スマホの 240fps スローモーションは **30fps のファイルとして書き出される**ことが多く、
その場合ファイル上の 8 秒が実際には 1 秒です。補正しないと速度が 1/8、加速度が 1/64 になります。

設定タブの「フレームレートと時間軸」で **撮影 fps**（撮影設定の数字）を指定してください。
ファイルの fps は自動計測されるので、入力するのは撮影 fps だけです。
未指定なら等倍で、通常の動画の挙動は変わりません。

## グラフ概形確認モード

「データ」タブの一番上。**縦軸（x / y / vx / vy / 速さ）** と **横軸（t / x / vx）** を別々に選ぶ方式で、
x-t, y-t, vx-t, vy-t, y-x, vy-vx をすべて含みます。定番の組み合わせはショートカットのチップから 1 タップ。
右上の「拡大」で全画面表示になります。

これは飾りではなく**検証の道具**として置いています。

- **グラフをタップするとその時刻へ動画がシークします**（再生中なら自動で止まります）。
  vx-t / vy-t に鋭いスパイクが出ていたらそこで追跡が飛んでいるので、タップして飛び、
  映像の「修正」ツールで直す、という流れになります。
- **y-x と vy-vx は等縮尺**で描きます。縦横の縮尺が違うと放物線が放物線に見えず、形の判断ができません。
  等縮尺のときは右上に「等縮尺」と出ます。
- **見失ったフレームでは線が切れます**。つないで描くと、追跡が飛んだ区間まで滑らかな曲線に見えて
  データが正しいと誤解するためです。
- 物体が複数あるときは色分けして重ね描きし、下の凡例をタップすると個別に表示を切り替えられます。

グラフは平滑化フィルタ適用後の値を描くので、フィルタの効き具合をその場で確認する用途にも使えます。

**表示だけの平滑化トグル**（既定 OFF）で、グラフの見た目からノイズを一段落とせます。
2 次 Savitzky-Golay なので放物線は鈍りません。CSV には影響しません。
ただし ON のあいだは追跡の飛びも見えにくくなるので、スパイクを探すときは OFF にしてください。

なお **a-t（加速度）は用意していません**。2 回微分はスマホ解像度のデータではノイズが支配的になり、
かえって誤った印象を与えるためです。

## 取りこぼしと再生速度

再生しながらの処理は `requestVideoFrameCallback` に乗っているので、1 フレーム分の処理が
実時間のフレーム間隔に間に合わないと、その間に提示されたコマは**呼ばれないまま通り過ぎます**。
「再生速度を落とすとうまく追える」のはこれが理由です。

取りこぼすと、記録の上では**1 コマの移動量が倍**（2 コマ落とせば 3 倍）になります。
探索窓が吸収すべき量もそれだけ増えるので、追跡が飛ぶ原因にもなります。

合成動画（480×320・30fps・3 秒 = 90 コマ）での実測です。

| やり方 | 記録できたコマ |
|---|---|
| 再生 1× | 41 / 90（46%） |
| 再生 1/4× | 88 / 90（98%） |

**1/4 でほぼ足ります。** 再生速度は 1/16 まで選べます（1/16 は Chrome が受け付ける
下限で、それより遅い値は例外になります）。

端末の速さに関係なく取りこぼしがゼロになる「全コマ処理」は **PC 版にあります**。
スマホでは長い動画に時間がかかりすぎて実用になりにくいので、再生バーからは外しました。

## データの取り出し

「データ」タブから 2 種類の CSV を出せます。**CSV 保存**、または **共有**
（Web Share API 対応端末）から書き出せます。iOS は共有シート経由の方が
ファイルアプリに確実に入ります。どちらも BOM 付き UTF-8。

- **CSV 保存** — 位置・速度・スコアまですべて。列構成は Ver.2 と同じ
- **位置だけの CSV** — 時刻と x, y だけ。速度も加速度も入っていません。
  **平滑化をかけていない生の位置**を出します。位置から速度を求める過程そのものが
  学習の中身なので、こちらのフィルタを通した値を渡すと、差分を取るとなぜノイズが
  荒れるのか、なぜ平滑化が要るのかを確かめられなくなるためです。
  そのぶん、この値は画面のグラフとは一致しません

### 単位

**出力はすべて m です。** 速度は m/s、加速度は m/s² になるので、教科書の式にそのまま入ります。
基準の長さを入力する欄だけは cm / mm を選べます。未校正のときは px のままです。

## 精度を出すコツ

- 枠は **20px 以上**。小さい枠は画面のどこにでも一致してしまい、軌跡が暴走します。
  ただし**必要以上に大きくしない**でください（マーカーとその周りが入れば十分）。
- **枠の中を物体の面で埋めてください。** 動かない背景が入るほど精度が落ちます（形状の差より一桁効きます）。
- マーカーは**白い丸シールではなく印刷したもの**を使ってください（回転しない対象は太い十字、回る対象は同心円）。
- 枠を置く前に **ピンチで拡大**してからタップすると、狙った位置に正確に置けます。
- 設定タブの **探索範囲**は上げすぎないでください（既定は 1.2）。これは上限の設定で、
  普段の窓は動きの変化から自動で決まります。広い窓は似た模様に乗り移る機会を増やすだけです。
- 取りこぼしが気になるときは **再生速度を落として**ください（1/2・1/4 で足りることが多いです）。
  端末の速さに関係なく取りこぼさない「全コマ処理」は PC 版にあります。
- 斜めから撮った映像は必ず **平面（四隅）校正**を使ってください。2点間校正では遠近の分がそのまま誤差になります。
- スロー動画では **撮影 fps を必ず設定**してください（忘れると加速度が 1/64 になります）。
- 頭と尻の使えない時間は **解析区間**で外してください（フィルタの自動遮断周波数が運動区間だけを見るようになります）。
- 手動記録では **細かく打ちすぎない**でください（実時間で 30〜50ms の間隔を空ける）。
- 平滑化は **Butterworth（自動遮断）** が推奨です。合成データではどの条件でも速度の誤差を
  35〜77% 減らしました。Savitzky-Golay は窓が時間として長すぎると逆効果になります
  （30fps で 7 点 = 233ms は明確に有害）。
