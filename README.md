# MotionTrace Mobile

トレースアプリ Ver.2 のスマートフォン専用版です。
追跡・スケール校正・平滑化のアルゴリズムは Ver.2 と同一（`src/utils/` をそのまま流用）なので、
同じ動画からは同じ数値が出ます。変えたのは **画面構成と入力方法だけ** です。

## 起動

```bash
npm install
npm run dev
```

`vite.config.ts` で `server.host: true` にしてあるので、起動時に表示される
`http://192.168.x.x:3000/` を同じ Wi-Fi のスマホで開けば実機で試せます。

ビルドは `npm run build`（出力は `dist/`）。

## 画面構成

```
┌──────────────┐
│ TopBar       │ OpenCV の準備状況・記録点数
├──────────────┤
│ 映像ステージ  │ ピンチズーム／パン、ツール操作
├──────────────┤
│ 再生バー      │ 再生・コマ送り・シーク・再生速度
├──────────────┤
│ シート        │ 対象／校正／設定／データ（高さ 3 段階）
├──────────────┤
│ タブバー      │
└──────────────┘
```

シートの上端の横棒はドラッグで高さを変えられます。タップで「半分 ⇄ 広い」、
同じタブをもう一度押すと閉じて映像が広くなります。

## 指の使い分け

映像の上では **指の本数で役割が変わります**。

| 操作 | 動き |
| --- | --- |
| 2本指ピンチ／ドラッグ | いつでも拡大縮小・移動 |
| 1本指 | 画面左のツールバーで選んだツールの操作 |

ツールは 6 種類です。

- **移動**（手のアイコン）— 1本指でも映像を動かす。誤操作を避けたいときの既定状態。
- **枠**（四角）— 追跡枠の指定。マーカーを**タップ**するとその点を中心に既定サイズの枠が置かれ、
  **ドラッグ**すれば任意サイズで囲めます。既定サイズは再生バーのスライダーで変更できます。
  枠の中は、マーカーと一緒に動くものだけで埋めてください（動かない背景が入ると精度が落ちます）。
- **修正**（十字矢印）— 一時停止中に、ずれた追跡点をドラッグして正しい位置へ直します。
  直せたかどうかは画面上部の帯に出ます。

画面上の追跡点・手動記録の点・修正の点は、**中心に隙間のある十字**で描いています。
塗りつぶした丸だと、狙っている画素そのものが自分の描画で隠れてしまうためです。
自動追跡の精度には影響しませんが、指で打つ・直すときの精度は変わります。
手動記録の誤差は 1/Δt² で速度・加速度へ拡大するので、狙いのばらつきが半分になれば
同じコマ送り幅で速度の誤差もそのまま半分になります。
- **手動記録**（カーソル）— コマごとに対象をタップして手でデータを作ります（下記）。
- **原点**（照準の的）— 座標の原点にしたい位置をタップします。
- **校正**（照準）— 校正タブで「指定を開始」を押すと現れます。

## 手動記録

自動追跡が使えない対象（変形する物体、低コントラスト、遮蔽が多い）はコマごとに手で指します。

1. コマごとに対象をタップする
2. そのコマの全対象を打つと、自動で設定コマ数だけ進む
3. 動画を 1 周すれば終わり

打つ順番は案内されますが、**物体チップを押せば指名**できます。取り消しは 1 点ずつ遡れます。
記録は自動追跡と同じデータに入るので、自動で追えた区間と混ぜて使えます。

**コマ送り幅が精度を決めます。** 加速度は 2 回微分なのでタップのぶれが 1/Δt² で拡大されます。
細かく打つほど良い、ではありません。合成データでは 1 コマおき（実時間 4.2ms）でばらつき 40.7%、
8 コマおき（33.3ms）で 0.7% でした。スライダーには実時間の間隔が ms で併記され、
撮影 fps から推奨値が自動で入ります。

ドラッグ中は指で隠れる部分を **虫めがね**（3倍）で表示します。数 px の精度が要るときはこれを見てください。

## マーカーの選び方

7 種類の形状を、追跡アルゴリズムそのもので 12,400 回試行して比べた結果です
（PC 版リポジトリの `scripts/marker-benchmark/`。印刷用 PDF もそこにあります）。

| 状況 | 推奨 | 位置誤差 |
|---|---|---|
| 回転しない対象（台車・落とす箱） | **太い十字**（腕幅 = 径の 1/4） | 0.069 px |
| 回転する対象（球・輪・振り子のおもり） | **同心円**（白 D / 黒 0.62D / 白 0.31D） | 0.078 px |
| 迷ったとき | **白地に黒丸**（黒の径 = 0.6D） | 0.116 px |
| （現行）白い丸シール | 非推奨 | 0.251 px |

大きさは画面上で **20〜30px**。実寸 = 視野の横幅 [mm] ÷ 横の画素数 [px] × 25。
線幅は画面上で 3px を切らないこと。

- **回転する対象に十字・市松・4分割を使わないでください。** 15 度回っただけで一致度が
  0.98 → 0.51 まで落ちます（LOST 判定は 0.45）。同心円と丸は 0.97 以上を保ちます。
- **方眼紙や目盛りのある背景では、白い丸シールが破綻します。** 実測で 150 回中 100 回、
  1px 以上外しました。印刷したマーカーは 7 種すべて破綻ゼロです。

**枠の中身**（誤差 13〜34 倍）のほうが形状の差（最大 4 倍）より一桁効きます。
まず枠の取り方を直してから、形状を検討してください。

## スケール校正

PC 版と同じ 3 モード（平面（四隅）／2点間／追跡枠の幅）です。スマホでは操作だけ変えています。

- **平面（四隅）**: 左上 → 右上 → 右下 → 左下 の順に**タップ**。
- **2点間**: 端から端まで**なぞる**か、**2回タップ**。
- 置いたあとは ● を直接ドラッグ、または校正タブの**十字キーで 1px ずつ**動かせます
  （キーボードが無いスマホでは、これが矢印キーの代わりです）。
- 校正が完了したあとは、タップしても点が置き直されません。
  やり直したいときは「四隅を取り直す」「線を引き直す」を押してください。

**原点**は「原点」ツールでタップして指定します。CSV の `X, Y` がその点からの値になります。
未指定なら画像の左下（`Y軸を上向き` が OFF なら左上）が原点です。

## 解析区間（時間範囲）

任意です。指定しなければ従来どおり動画全体を使います。

実験動画の頭と尻には、必ず使えない時間が入ります。装置の準備、手がフレームに入っている区間、
着地後の跳ね返り、転がって止まるまで。これを含んだまま解析すると 2 つが壊れます。

- **Butterworth の自動遮断周波数** — 記録全体に対して遮断周波数を 1 つ選ぶので、静止区間や
  衝突の不連続が混ざると、肝心の運動区間に対して不適切な値が選ばれます。
- **中心差分** — 衝突の瞬間をまたいだ 1 点だけ、物理的に意味のない速度が出ます。

### 使い方

再生バーの下の **始点 / 終点 / 解除** で指定します。

1. 運動が始まるコマまでコマ送りし、**「始点」**
2. 運動が終わるコマまで進めて、**「終点」**

片側だけの指定もできます。シークバーには区間が帯で表示されます。

### 何に効くか

区間は **記録と解析の両方**に効きます。

| | 動き |
|---|---|
| 記録 | 区間外は追跡も記録もしない。**終点で自動停止**する |
| 再生 | 区間の外から再生を始めると、まず始点へ送ってから再生する |
| やり直し | 動画の先頭ではなく**区間の始点**へ戻る（軌跡は消え、枠は初期位置へ戻る） |
| 解析 | グラフ・フィルタ・CSV が区間内のデータだけを使う |

終点の自動停止があるので、片手で端末を持ったまま「終わりを見張って停止ボタンを押す」
必要がなくなります。押し遅れて余分なフレームが混ざる事故もこれで消えます。

**あとから狭めるのは非破壊です。** 記録済みのデータは残るので、区間を狭めればグラフ・CSV が
その区間だけを使い、広げれば元に戻ります。取り直しは不要です。

区間内が **20 点を切ると警告**が出ます。Butterworth はデータから遮断周波数を決めるので、
点数が減ると選択そのものが不安定になります。

区間は「この動画の何秒から何秒まで」なので、動画を読み込み直すと解除されます。

## やり直し（取り直し）

再生バーの **やり直し**（↺）は 3 つを同時に行います。

1. 記録した軌跡を消す
2. **追跡枠を、戻る先のコマで物体がいた位置へ戻す**
3. 記録が始まる時刻へ送る（区間の始点 → 無ければ枠を置いたコマ → 無ければ先頭）

2 が要る理由は、枠が追跡中に毎フレーム上書きされるからです。追跡が終わった時点で
枠に入っているのは「物体が最後に到達した位置」なので、それを残したまま巻き戻すと、
物体のいない場所でテンプレートが作り直され、その場で破綻します。

**戻す先は 2 段階です。**

- 直前の走行の軌跡が残っていれば、**戻る先のコマ（＝ 3 の時刻）でその物体がいた位置**へ
  枠を移します（大きさは変えません）。
- 軌跡がまだ無ければ、最初に置いた位置へ戻します。

最初に置いた位置へ戻すだけだと、区間の始点をあとから動かした場合や、物体ごとに別のコマで
枠を置いた場合に、**枠と映像が別のコマを指したまま**になります。これが
「やり直すたびに枠を置き直す」原因でした。

結果として **同じ区間・同じ初期枠なら、何度取り直しても同じ数値が出ます。**

手動で打った点があるときは、消える点数を示して確認します。

### 枠を置いたコマと区間の始点

テンプレートは **枠を置いた瞬間のコマの画**から作られます。区間の始点がそのコマとずれていると、
始点のコマに物体がいない＝追跡が始まらない、ということが起きます。
ずれているときは警告と **「枠のコマを始点に」** ボタンが出ます。

複数の物体の枠を別々のコマで置いた場合も警告します。戻れるコマは 1 つしかないので、
どちらかは必ず外れます。

## 時間軸（スロー動画）

スマホの 240fps スローモーションは **30fps のファイルとして書き出される**ことが多く、
その場合ファイル上の 8 秒が実際には 1 秒です。補正しないと速度が 1/8、加速度が 1/64 になります。

設定タブの「フレームレートと時間軸」で **撮影 fps**（撮影設定の数字）を指定してください。
ファイルの fps は自動計測されるので、入力するのは撮影 fps だけです。
未指定なら等倍で、通常の動画の挙動は変わりません。

## グラフ概形確認モード

「データ」タブの一番上。**縦軸（x / y / vx / vy / 速さ）** と **横軸（t / x / vx）** を別々に選ぶ方式で、
x-t, y-t, vx-t, vy-t, y-x, vy-vx をすべて含みます。定番の組み合わせはショートカットのチップから 1 タップ。
右上の「拡大」で全画面表示になります。

これは飾りではなく**検証の道具**として置いています。

- **グラフをタップするとその時刻へ動画がシークします**（再生中なら自動で止まります）。
  vx-t / vy-t に鋭いスパイクが出ていたらそこで追跡が飛んでいるので、タップして飛び、
  映像の「修正」ツールで直す、という流れになります。
- **y-x と vy-vx は等縮尺**で描きます。縦横の縮尺が違うと放物線が放物線に見えず、形の判断ができません。
  等縮尺のときは右上に「等縮尺」と出ます。
- **見失ったフレームでは線が切れます**。つないで描くと、追跡が飛んだ区間まで滑らかな曲線に見えて
  データが正しいと誤解するためです。
- 物体が複数あるときは色分けして重ね描きし、下の凡例をタップすると個別に表示を切り替えられます。

グラフは平滑化フィルタ適用後の値を描くので、フィルタの効き具合をその場で確認する用途にも使えます。

**表示だけの平滑化トグル**（既定 OFF）で、グラフの見た目からノイズを一段落とせます。
2 次 Savitzky-Golay なので放物線は鈍りません。CSV には影響しません。
ただし ON のあいだは追跡の飛びも見えにくくなるので、スパイクを探すときは OFF にしてください。

なお **a-t（加速度）は用意していません**。2 回微分はスマホ解像度のデータではノイズが支配的になり、
かえって誤った印象を与えるためです。

## 取りこぼしをゼロにする — 「全コマ処理」

再生しながらの処理は `requestVideoFrameCallback` に乗っているので、1 フレーム分の処理が
実時間のフレーム間隔に間に合わないと、その間に提示されたコマは**呼ばれないまま通り過ぎます**。
「再生速度を落とすとうまく追える」のはこれが理由で、遅くするのは取りこぼす確率を
下げているだけで、ゼロにはなりません。端末の処理が追いつきにくいスマホでは差が大きく出ます。

再生バーの **「全コマ」** は再生せずに「次のコマへシーク → 処理」を繰り返すので、
端末の速さに関係なく取りこぼしが原理的に起きません。そのぶん実時間はかかります。
解析区間を指定していればその範囲だけを処理し、途中で中止できます。

合成動画（480×320・30fps・3 秒 = 90 コマ）を実際に処理させた実測です。

| やり方 | 記録できたコマ |
|---|---|
| 再生 1× | 41 / 90（46%） |
| 再生 1/4× | 88 / 90（98%） |
| **全コマ処理** | **90 / 90（100%）** |

再生速度は 1/16 まで選べます（1/16 は Chrome が受け付ける下限で、それより遅い値は
例外になります）。それでも足りないときは速度ではなく「全コマ」を使ってください。

## データの取り出し

「データ」タブから 2 種類の CSV を出せます。**CSV 保存**、または **共有**
（Web Share API 対応端末）から書き出せます。iOS は共有シート経由の方が
ファイルアプリに確実に入ります。どちらも BOM 付き UTF-8。

- **CSV 保存** — 位置・速度・スコアまですべて。列構成は Ver.2 と同じ
- **位置だけの CSV** — 時刻と x, y だけ。速度も加速度も入っていません。
  **平滑化をかけていない生の位置**を出します。位置から速度を求める過程そのものが
  学習の中身なので、こちらのフィルタを通した値を渡すと、差分を取るとなぜノイズが
  荒れるのか、なぜ平滑化が要るのかを確かめられなくなるためです。
  そのぶん、この値は画面のグラフとは一致しません

### 単位

**出力はすべて m です。** 速度は m/s、加速度は m/s² になるので、教科書の式にそのまま入ります。
基準の長さを入力する欄だけは cm / mm を選べます。未校正のときは px のままです。

## 精度を出すコツ

- 枠は **20px 以上**。小さい枠は画面のどこにでも一致してしまい、軌跡が暴走します。
- **枠の中を物体の面で埋めてください。** 動かない背景が入るほど精度が落ちます（形状の差より一桁効きます）。
- マーカーは**白い丸シールではなく印刷したもの**を使ってください（回転しない対象は太い十字、回る対象は同心円）。
- 枠を置く前に **ピンチで拡大**してからタップすると、狙った位置に正確に置けます。
- 端末が重そうなら、設定タブの **探索範囲**を上げすぎないでください（既定は 1.2。速い物体を見失うときだけ少しずつ上げます）。
- 取りこぼしが気になるときは、再生速度を落とすより **「全コマ」** を使ってください（実測で 100%）。
- 斜めから撮った映像は必ず **平面（四隅）校正**を使ってください。2点間校正では遠近の分がそのまま誤差になります。
- スロー動画では **撮影 fps を必ず設定**してください（忘れると加速度が 1/64 になります）。
- 頭と尻の使えない時間は **解析区間**で外してください（フィルタの自動遮断周波数が運動区間だけを見るようになります）。
- 手動記録では **細かく打ちすぎない**でください（実時間で 30〜50ms の間隔を空ける）。
- 平滑化は **Butterworth（自動遮断）** が推奨です。合成データではどの条件でも速度の誤差を
  35〜77% 減らしました。Savitzky-Golay は窓が時間として長すぎると逆効果になります
  （30fps で 7 点 = 233ms は明確に有害）。

## PC 版との差分

| | Ver.2（PC） | Mobile |
| --- | --- | --- |
| レイアウト | 2カラム | 1カラム＋ボトムシート |
| 入力 | マウス | Pointer Events（1本指＝ツール／2本指＝ズーム） |
| 枠の指定 | ドラッグのみ | タップ配置＋ドラッグ |
| 校正点の微調整 | 矢印キー | 十字キー（画面上） |
| 拡大 | 25%刻みボタン | ピンチ（等倍〜12倍）＋ボタン |
| 位置合わせ補助 | なし | 虫めがね |
| CSV | ダウンロード | ダウンロード＋共有シート |
| グラフ | 概形確認モード | 同じ（タップでシーク） |
| 手動記録 | あり | あり（タップで記録） |
| 追跡アルゴリズム | — | **同一** |

`src/components/{Header,VideoCanvas,ControlPanel,DataPanel}.tsx` は Ver.2 の名残で、
現在は使われていません（中身は空のスタブ）。

## 共通コードについて

`src/utils/` と `src/types/` は PC 版
[tracker_PC](https://github.com/Shin-phys/tracker_PC) からの**同期コピー**です。
**このリポジトリ側で編集しないでください**（次の同期で上書きされます）。
共通コードを直すときは PC 版を編集し、PC 版で `npm run sync:core` を実行します。
詳細は `src/utils/README.md` を参照してください。
